Because negotiating with every pixel individually is a poor use of an evening, here is a little project I've been building for prop assembly and testing: PixelTool, with Home Assistant access and Baldrick output support.

The idea is to upload a supported custom .xmodel, keep it in a private model library, and use the same colours on the reference map and the physical pixels while testing or pushing a prop.

Current tools include:

• Pixel finder, automatic walk and inclusive range tests.
• Strand cutter with boundary colours, final-cut marker and optional tail.
• Solid colours, rainbow, scan and RGB wipe.
• Model pushing with colour runs, white/markers, focus and locate.
• Checkpoint editing, previous/next, front/rear views, zoom/fit and node numbering.
• Saved prop instances, controller/port assignments and first-model-node offsets for partially connected props.

MARK compares the positions you select; it doesn't detect physically inserted pixels. Imported string boundaries are suggestions until confirmed, not automatically verified pushing checkpoints.

Patterns render on a local companion service and go out as DDP. It uses existing controller mappings and doesn't modify active xLights files. You do need to stop xLights/FPP output during a test—software ownership doesn't lock out another DDP sender.

Baldrick8 and Baldrick17 output has been exercised on my display. The ESP32-C6 tester also now works as a network destination, while retaining its standalone GUI. I'm aiming to put that in a portable battery-powered yard tester; the battery enclosure/power setup and connected-prop validation are still to come.

It's an early personal project, not a public download yet. Current imports cover contiguous, numbered custom RGB models; some other model structures are deliberately rejected rather than silently changed.
